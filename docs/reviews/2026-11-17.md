# Hoomail review: November 17, 2026

Reviewed the working tree based on `905591d` (application version `0.10.2`). The most consequential findings were that two configured database paths could share mail, and that a browser could open and mark a replacement message read after its numeric ID was reused.

## Confirmed findings and repairs

| Area | What failed | What changed and how it was checked |
| --- | --- | --- |
| SQLite files | Two ordinary paths with different text after `?` opened the same database. | Literal paths now open distinct files. Tests stored mail, closed the database, and reopened both paths. An explicit `file:` URI still retains its SQLite options and connection pragmas. |
| Reader and bulk selection | A reset missed by the browser left the reader and selection pointing at replacement mail. A delayed first stream greeting had the same effect: Chromium showed the new message with zero unread before anyone selected it. | Stream greetings and committed resets carry an opaque generation. A matching reconnect preserves the reader. If the generation changed or the selection predates the first greeting, the client clears it before fetching details. Three [browser cases](../../e2e/resilience.spec.ts) cover these paths. |
| HTTP | Browser requests from another origin reached state-changing handlers, including the detail GET that marks a message read. Some mail and error responses allowed storage by caches. | State-changing requests now pass Go's browser origin check; same-origin requests and direct API clients still work. Mail, errors, and the event stream declare `private, no-store`; the stream also keeps `no-transform`. [Handler tests](../../internal/httpserver/httpserver_test.go) cover the policy and generated API contract. |
| POP3 | `TOP 0` could include body text when headers were empty or line endings were mixed. A large set of deletions could exceed SQLite's bind limit at `QUIT`. | `TOP` stops at the first empty physical line. Deletes use bounded statements in one transaction. With a 999-parameter limit, a [1,200-message test](../../internal/store/store_test.go) forced the last deletion to fail, verified that all messages remained, then retried successfully. |
| Store ordering and cancellation | Messages delivered in one millisecond appeared oldest first. Three cancelled operations behind a held storage lock left six helper goroutines waiting. | Descending message ID breaks timestamp ties, including in search. A cancellable gate replaces the helper goroutines; the same contention probe found zero remaining workers. |
| MIME and calendar | A forwarded message inside an unselected MIME alternative supplied an invitation to the enclosing email. In the calendar, deleting a source left a clickable entry, and opening a cached source hidden by search could leave it unread. | [Parser coverage](../../internal/smtpserver/parser_test.go) keeps forwarded invitations separate. [Browser tests](../../e2e/calendar.spec.ts) verify that a deleted source is disabled, a later update re-enables it, and opening a filtered source marks it read. Calendar history and its stored provenance are preserved. |
| Image build and smoke test | The compile stage downloaded Go dependencies a second time. The smoke script kept using the old host port after Docker changed it on restart and trusted supplied ports independently of the named container. | The build retains downloaded modules and compiles with networking disabled. The smoke script verifies the named container's loopback mappings before reset and reads them again after restart. A mismatched test port was rejected without connecting to it. |

## Open dependency advisory

The production Bun audit reported no findings. The full audit reported one high-severity advisory, [GHSA-fc5q-39xc-vjpf](https://github.com/advisories/GHSA-fc5q-39xc-vjpf), for `picomatch` in the Vite and Preact build tooling. On November 17 the advisory listed versions through `4.0.7` as affected and no patched release. No dependency override or audit suppression was added. Recheck the advisory when updating the development lockfile.

## Upgrade note

If an existing `HOOMAIL_DB_PATH` contains a literal `?`, locate and back up the database that holds the mail before upgrading. Older versions could have written to the filename before the first `?`. The new version does not move or merge files. See [SQLite path and backup guidance](../data-and-calendar.md).

The SQLite schema and image version are unchanged. The browser origin check does not add authentication. Validation used disposable local instances; no release or deployment was performed.
