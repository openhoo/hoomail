# Hoomail review and smoke testing: October 13, 2026

Three reviewers covered the browser and frontend; MIME, inspection and HTTP
security; and SMTP, POP3, calendar, SQLite storage and events. Confirmed findings
were reproduced with failing regressions, repaired, and cross-reviewed. An
integration pass checked dependencies, the full application, both container
architectures, and persistent database restart behavior.

## Repairs

| Area | Findings addressed |
| --- | --- |
| SMTP/BDAT | Preserve payload bytes when commands and chunks share a TCP write; reject truncated final chunks before delivery; wait for active Data callbacks before session cleanup. |
| POP3 | Close listeners supplied after terminal shutdown; reject embedded CR command framing. |
| Calendar | Reject overflowing durations and event ends outside the persisted millisecond range while preserving valid signed durations. |
| SVG preview | Reject escaped or commented CSS URLs that could resolve to external resources. Browser smoke independently reproduced the attempted request. |
| MIME parsing | Share structural budgets across decoded encapsulated messages; preserve attachment-only root message/rfc822 and message/global wrappers, filenames and nested headers. |
| Inspection | Use the correct decoded source for boundary checks; omit unavailable original-wire byte sizes and line coordinates; reject lone CR header controls; report nested source lines correctly; produce bounded partial reports for incomplete multipart input and oversized metadata. |
| UI recovery | Show loading and errors for inbox, messages and calendar; add Retry for failed resources; report mutation failures; reconcile readers and selections after external deletion. Preserve reading context during inbox Retry and expose failures of the full-inbox dependency during search. |
| Mobile | Keep controls reachable with long headers and wrap bounded MIME metadata at phone widths. |
| Dependencies | Pin Go 1.26.9 and patched Go dependencies; update nanoid and source-map-js overrides; repair newly activated printf vet findings in the SMTP fork. |
| Verification | Compare iframe fonts with the browser's actual default. Validate authoritative store generations, counts and orphan-free persistence without imposing total ordering on concurrent invalidations. |
| CI | Replace the Docker health-only smoke step with 28 workflow checks and a real SQLite restart through scripts/smoke.py. |

The storage changes concern tests and documentation. Sequential event-order and
blocked-broadcaster regressions remain; production invalidation semantics and
the event schema are preserved. HTTP schemas and database schemas are unchanged.
Malformed protocol frames and overflowing calendar durations now fail closed.

Both final images passed ordinary and hardened smoke runs. Hardened runs used
a read-only root filesystem, all capabilities dropped, no-new-privileges,
64 MiB memory, separate disposable SQLite directories, and loopback-only port
mappings. Neither final container was OOM-killed. The Docker host was arm64;
amd64 executed through architecture emulation, so these checks do not establish
native amd64 performance. All review containers and disposable databases were
removed after verification.

The smoke checks cover embedded UI assets, OpenAPI, SSE delivery invalidation,
normalized envelope/Bcc delivery, exact source and deterministic inspection,
read/unread state, literal search, HTML/CID safety, attachment bytes and execution
policy, POP3 retrieval/dot handling/delete commit semantics, calendar
invite/update/cancellation, concurrent SMTP, valid and truncated BDAT,
declared size limits, restart persistence, deletion cascades, and reset.

## Compatibility and rollback

The SMTP fork remains a local replacement with its provenance and licenses
preserved. Go source builds now require Go 1.26.9 or newer. Container entrypoints,
ports, persistent storage paths, chart deployment strategy and HTTP schemas
retain their existing contracts. No data migration or database reset is needed
to deploy these fixes. Rollback uses the previous image/chart version with the
existing persistent volume; it also restores the defects documented above.

These are recorded local results. Publication CI and release jobs provide their
own checks for the final remote revision. Bounded fuzzing and smoke tests cover
the exercised cases and do not prove the absence of all malformed inputs.
