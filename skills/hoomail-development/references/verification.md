# Focused verification

Commands run from the Hoomail source root unless noted otherwise.

## SMTP fork

Read `third_party/go-smtp/README.openhoo.md` before patching or updating the
fork. Preserve its upstream license and recorded provenance. Run:

```bash
go test -race ./internal/smtpserver
```

Then, from `third_party/go-smtp`, run `go vet ./...` and `go test ./...`.
The main module uses a local replacement; the nested module is not tested by
top-level `go test ./...`. Check exact DATA size limits and rejected/non-LAST
BDAT handling whenever changing stream/parser logic.

## HTTP/OpenAPI

The spec is generated by `internal/httpserver/openapi_generate.go`, not inferred
from handler signatures. After changes to the generator:

```bash
go generate ./internal/httpserver
go test -race ./internal/httpserver
```

Include `internal/httpserver/openapi.json` and corresponding documentation.
Check mixed JSON/plain-text errors, route shapes, field casing, and read-state
side effects rather than assuming a uniform API contract.

## Browser harness

`e2e/run-server.ts` builds a fresh binary and owns its server; no server reuse.
Defaults are HTTP 33100, SMTP 33125, POP3 33126. Configure
`HOOMAIL_E2E_HTTP_PORT`, `HOOMAIL_E2E_SMTP_PORT`, and
`HOOMAIL_E2E_POP3_PORT` for conflicts. POP3 otherwise uses SMTP plus one.
Runs use one Chromium worker, locale `en-US`, timezone `UTC`. Failure artifacts
are in `playwright-report/` and `test-results/`; traces are captured on retry.

Inspection browser changes need a valid MIME fixture accepted by the SMTP
parser, a no-external-network assertion, and the explicit 500/retry/loading/
success lifecycle already described in `docs/development.md`.

## Chart

```bash
helm lint --strict charts/hoomail
helm template hoomail charts/hoomail > /dev/null
helm template hoomail charts/hoomail \
  --set persistence.enabled=false --set ingress.enabled=true \
  --set ingress.className=nginx > /dev/null
helm template hoomail charts/hoomail \
  --set persistence.existingClaim=hoomail-data \
  --set serviceAccount.create=true --set serviceAccount.name=hoomail > /dev/null
bun scripts/sync-chart-version.ts --check
```

Use additional digest/security/schema variants from CI when touching those
values. Version checks do not authorize a version bump or release.

## Performance and persistence

For parser changes, retain the SMTP-facing wrapper measurement:

```bash
go test ./internal/mimeparse ./internal/smtpserver \
  -run '^$' -bench 'Benchmark(Parse|ParseMIME)' -benchmem -benchtime=1s -count=5
```

`bun run bench:frontend` measures the large-list browser scenario. Benchmarks
are observations, not pass/fail thresholds. Storage changes affecting restart
behavior need an actual disposable database restart check; ordinary unit/E2E
and image-health tests do not demonstrate durable persistence.
